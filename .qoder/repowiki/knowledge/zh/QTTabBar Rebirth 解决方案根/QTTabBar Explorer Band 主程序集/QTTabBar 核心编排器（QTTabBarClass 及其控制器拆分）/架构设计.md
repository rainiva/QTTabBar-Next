本模块以 `QTTabBarClass`（继承自 `TabBarBase`，通过 `[ComVisible]` + `Guid` 注册为 COM BandObject）为核心，采用“主类 + 多个 partial 文件”的拆分方式，将原本臃肿的单文件逐步拆分为按职责划分的控制器：
- `QTTabBarClass.cs`：保留 COM 入口、字段声明、构造函数、属性与对子控制器的转发方法，是所有控制器的装配点。
- `ComponentBuildController.cs`：实现 `IComponentBuildHost`/`ITabBarCompositionHost`/`IShutdownResourceHost`/`IShutdownPersistenceHost`，负责 UI 控件构造、事件连线、IPC 合并标签、插件选项打开以及关闭期资源暴露。
- `ShellHosts.cs`：集中实现所有被控制器反向依赖的 Host 接口（`IBindActionHost`、`IHookInputHost`、`IQTTTabBarBandHost`、`IShellNavigationHost` 等），把宿主能力以窄接口暴露给控制器。
- `ExplorerController.cs`：面向 Explorer 交互的聚合控制器，持有大量 `IExplorer*Host` 字段并组合出 `ExplorerSessionRestoreController`、`ExplorerNavigationController`、`ExplorerTravelLogController` 等子控制器，形成二级分层。
- `BindActionController.cs`：处理 `BindAction` 枚举分派，仅依赖 `IBindActionHost`/`IBindActionUiHost` 与 `MenuController`，不直接引用 `QTTabBarClass`。
- `ShutdownController.cs`：封装 `CloseDW` 中的释放/持久化逻辑，依赖 `IShutdownResourceHost`/`IShutdownPersistenceHost`。

依赖方向严格单向：控制器 → Host 接口 → `QTTabBarClass`；`QTTabBarClass` 自身只持有各控制器实例并通过 internal 方法转发调用，避免循环引用。该模式由 `merge-partials.py` 批量生成 partial 文件头注释标识来源批次，是本次架构重构的产物。
