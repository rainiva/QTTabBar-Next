## 目标与约束

**目标**：全面诊断 + 分批治理三大痼疾，产出可持续推进的重构路线（覆盖多入口、多真源、上帝模块）。

**硬约束（不可破坏的契约）**：

- **未经明确要求不 commit**。
- WPF 构建用 `MSBuild.exe`，不能只靠 `dotnet build`。

## 现状诊断（三痼疾定位）

### 1. 多入口（初始化分散）
- 主入口：[QTUtility 静态构造](file:///d:/Project/QTTabBar-Next/QTTabBar/QTUtility.cs#L177-L318)，串行触发 `ConfigManager.Initialize`(L209) → `InstanceManager.Initialize`(L213) → `HookLibManager.Initialize`(L217) → `ImageListGlobal`(L221) → `GroupsManager.LoadGroups`(L226) → `AppsManager.LoadApps`(L229) → 语言(L232) → 注册表 `RecentlyClosed/RecentFiles/NoCaptureAt/WindowAlpha`(L237-264) → `GetShellClickMode`(L307) → `PluginManager.Initialize`(L311)。
- 冗余入口：`QTTabBarClass` 构造再调 `QTUtility.Initialize()` 且重复调用 `HookLibManager.Initialize()`；`OptionsDialog`/预览宿主也调 `ConfigManager.Initialize()`。
- 问题：初始化顺序隐式、多处重复、竞态与顺序脆弱。

### 2. 多真源（配置/状态分散）
- 真源1：`QTUtility` 静态字段（`ImageListGlobal`/`DisplayNameCacheDic`/`TextResourcesDic`/`ITEMIDLIST_Dic_Session`/`NoCapturePathsList`/`WindowAlpha` 等）。
- 真源2：[ConfigManager.LoadedConfig](file:///d:/Project/QTTabBar-Next/QTTabBar/Config.cs#L1129-L1155) 内存单例。
- 真源3：注册表（`ReadConfig` L1155 读、`UpdateConfig` L1139 / `WriteConfig` L1279 写）。
- 真源4：IPC 广播（各进程收到 `ReloadConfig` 后各自重读注册表，存在写-读竞态与乱序）。
- 问题：状态分布四处、来源难追踪、跨进程一致性弱。

### 3. 上帝模块（巨型类）
- `QTTabBarClass.cs`（7783 行）：UI + 菜单 + 拖拽 + 导航 + Hook + 插件 + IPC 混在一起。
- `QTUtility.cs`（1317 行）：初始化协调 + 全局缓存 + 图标 + 资源 + 路径/Shell 工具。
- `InstanceManager.cs`（670 行）：WCF 通道 + 实例注册 + 广播（部分已提取）。

## 风险与缓解

| 风险 | 等级 | 缓解 |
|------|------|------|
| 初始化顺序变动致功能失效/NPE | 高 | 原样移入序列不重排；编排幂等 + 顺序断言测试 + Explorer 启动验证 |
| Config 序列化/`_Skin` 兼容破坏 | 极高 | Task 0 往返测试先行；仅加适配层，不改读写逻辑 |
| IPC 乱序/格式破坏多进程 | 高 | 版本号为可选附加字段，保持向后兼容；契约往返测试 |
| 插件 ABI 破坏 | 极高 | `QTPluginLib` 接口冻结，提取只在 internal 层 |
| 提取致 UI 崩溃 | 高 | 小步提取、façade 保留旧入口、每批回归 + 预览/真实路径双验 |
| 静态字段线程安全回归 | 中 | 沿用现有锁语义，替换并发容器时以特征化测试覆盖 |

## 被否决的替代方案

- **Alex 的完整 DI 容器 + AppState/ConfigSyncCoordinator 大架构**：引入 IoC、重写状态与配置同步层，改动面与回归风险过大，且与代码库既有的「façade + 批次」范式和用户「反对过度设计」的偏好冲突。→ 仅吸收其「初始化编排、配置版本号」思想，落到最小实现。
- **Sam 的运行时性能改造（Hook 异步化、初始化并发、Monitor→ManualResetEvent、IPC 消息队列）**：改变初始化时序与线程模型，属行为变更，违反「逻辑不动」硬约束，且需性能基准支撑。→ 作为**独立的后续性能专项**延后，不纳入本轮结构治理。
- **一次性大爆炸重写巨型类**：回归不可控。→ 坚持单职责逐批绞杀。
